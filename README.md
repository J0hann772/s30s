# s30s
Портал с конспектами для подготовки

## Как открыть
Двойной клик по `index.html` — работает из проводника (`file://`), без сервера и **без интернета**:
KaTeX лежит локально в `vendor/katex/`; внешних скриптов и CDN нет.

## Структура
```
index.html              разметка страницы и политика CSP
style.css               стили
app.js                  рендерер markdown + KaTeX, главная с карточками, навигация, поиск, прогресс, карточки, вариант с таймером
manifest.js             настройки (S30S_CONFIG) и список предметов и контрольных (грузится всегда, маленький)
server/nginx-security.conf  заголовки безопасности и закрытие служебных файлов для nginx
deploy.sh / deploy.ps1 / deploy.cmd  деплой одной командой
data/matan-rk1.js       данные одной контрольной: topics, exam, discrepancies, traps, figures
notes/matan-rk1/*.md    исходные конспекты этой контрольной (источник правды)
tools/build_data.py     собирает data/<id>.js из notes/<id>/
vendor/katex/           KaTeX 0.16.11 (js, css, шрифты woff2) для офлайна
```
Главная страница (`#/`) — карточки контрольных из `manifest.js`; клик открывает материал именно этой контрольной. Нужный файл данных подгружается через `<script>`, поэтому всё работает и по `file://`.

## Правка контента
1. Править `notes/matan-rk1/*.md`.
2. Пересобрать данные:
   ```
   python tools/build_data.py notes/matan-rk1 notes/matan-rk1/93_block_b_figs.json data/matan-rk1.js
   ```
3. Обновить страницу.

Формат конспектов: обычный markdown + `$...$` / `$$...$$`; `<details><summary>…</summary> … </details>` — сворачиваемые доказательства/решения;
строки с `>` и ⚠️ — блок «расхождение со слайдами»; «**Пример…**» + `<details><summary>Решение</summary>` — пример со скрытым решением.
Пометка `[не из лекций]` подсвечивается автоматически.

## Новая контрольная
1. `notes/<id>/` с конспектами, свой список тем/вопросов в копии `tools/build_data.py` (или параметризовать скрипт).
2. `data/<id>.js` — вызывает `S30S.register({ id: "<id>", topics, exam, discrepancies, traps, figures })`.
3. Добавить запись в `manifest.js`: `{ id, title, date, data: "data/<id>.js" }`.

## localStorage
Ключи с префиксом id контрольной — прогресс РК1 и РК2 не смешивается:
- `matan-rk1:topic:<topicId>:read` — тема прочитана
- `matan-rk1:exam:<A1|B2|C3…>:known` — вопрос теории «знаю»
- `matan-rk1:task:<1.1…>:done` — задача решена
- `matan-rk1:variant:*` — таймер и баллы типового варианта
- `matan-rk1:disc:onlyMajor` — фильтр расхождений

Общие для всех контрольных: `s30s:theme`, `s30s:lastExam`.

## Известные ограничения
- **Общие темы между контрольными дублируются.** Темы по пределам понадобятся и в РК2 — пока они будут скопированы в `data/matan-rk2.js`.
  Как вынести потом: завести `data/shared/<subject>-<topic>.js`, где каждая тема регистрируется отдельно
  (`S30S.registerTopic({ id: "matan:limits-remarkable", … })`), в файле контрольной хранить только ссылки на id тем,
  а в `manifest.js` у контрольной — список shared-файлов (`deps`), которые оболочка подгружает перед ней.
  Ключи прогресса тем тогда перевести на id темы (`matan:topic:<id>:read`), чтобы «прочитано» переносилось между РК.
- **⚠️ в конспектах и раздел «Расхождения» хранятся раздельно** (текст ⚠️ внутри темы + отдельный массив `discrepancies`),
  а не как ссылка на один источник. При правке расхождения менять оба места (`notes/…/98_discrepancies.md` и саму тему).
- Мини-рендерер markdown понимает подмножество: заголовки, абзацы, списки (один уровень вложенности), таблицы, цитаты, жирный/курсив, `code`, ссылки.
- Дальше — переезд на Django (данные уже отделены от рендеринга: `data/*.js` = JSON внутри `S30S.register(...)`).

## Название

s30s читается как «study of the '30 students»: учёба студентов выпуска 2030, кафедра ИУ7 МГТУ им. Н. Э. Баумана. Логотип: знак «30» в рамке и слово s30s с акцентом на «30» (CSS и встроенный SVG-значок вкладки, без внешних файлов).

## Деплой

Сервер: git pull в `/var/www/cheatsheet`, раздаёт nginx. Скрипт в корне делает всё одной командой:

    .\deploy.cmd                  # Windows (PowerShell), дерево должно быть чистым
    .\deploy.cmd -m "текст"       # закоммитить все изменения этим сообщением и задеплоить
    .\deploy.cmd -DryRun          # только показать команды
    ./deploy.sh [-m "текст"] [--dry-run] [--no-build]   # Git Bash / WSL / Linux

Шаги: 1) пересборка `data/*.js` из `notes/` (список сборок в начале скрипта — добавьте строку для новой контрольной); 2) `git push origin main` (без `-m` скрипт сам ничего не коммитит и остановится, если есть незакоммиченные изменения); 3) `ssh` на сервер и `git pull --ff-only`; 4) проверка, что сайт отвечает HTTP 200.

Настройки: скопируйте `deploy.conf.example` в `deploy.conf` (файл в `.gitignore`) и укажите `DEPLOY_USER`, при необходимости хост, путь и адрес сайта. Нужен вход на сервер по ssh-ключу.

## Режим без персонализации

В `manifest.js` строка `window.S30S_CONFIG = { progress: true };`. Значение `false` убирает «прочитано», «знаю», «решил сам», счётчики и отметки карточек, и ничего из этого не пишется в браузер. Останутся только настройки вида (тема, размер текста, свёрнутые разделы). Ни аккаунтов, ни cookie, ни запросов на сервер сайт не использует.

## Безопасность (минимум для статического сайта)

- Нет внешних скриптов, стилей и шрифтов; нет inline-скриптов. В `index.html` задана CSP (`script-src 'self'`, `default-src 'none'`), политика действует и при открытии из файла.
- Весь вывод экранируется (включая кавычки); в markdown-ссылках разрешены только `#...` и `https://...` (с `noopener`). Адрес вида `#/search/...` больше не позволяет внедрить HTML.
- На сервере подключите `server/nginx-security.conf` внутрь блока `server { }` (затем `sudo nginx -t && sudo systemctl reload nginx`): он закрывает `.git`, `tools`, `notes`, скрипты деплоя, разрешает только GET/HEAD и добавляет заголовки (CSP с `frame-ancestors`, nosniff, HSTS, Referrer-Policy, Permissions-Policy). Самое важное: `.git` лежит в `/var/www/cheatsheet`, без этого блока репозиторий можно скачать по HTTPS.
- `deploy.sh` после выкладки проверяет, что `/.git/HEAD` и другие служебные файлы отвечают не 200, и сообщает об отсутствующих заголовках.
- Другие пакеты в браузере не ставятся, зависимостей npm нет, поэтому риск цепочки поставок ограничен KaTeX в `vendor/`.
