# s30s
Портал с конспектами для подготовки

## Как открыть
Двойной клик по `index.html` — работает из проводника (`file://`), без сервера и **без интернета**:
KaTeX лежит локально в `vendor/katex/`; внешних скриптов и CDN нет.

## Структура
```
index.html              разметка страницы и политика CSP
style.css               стили
app.js                  рендерер markdown + KaTeX, главная с карточками, навигация, поиск, прогресс, карточки, вариант с таймером
widgets.js              интерактивные иллюстрации в конспектах (маркер `{{widget:имя}}` в md или поле `widget` у вопроса)
manifest.js             настройки (S30S_CONFIG) и список предметов и контрольных (грузится всегда, маленький)
server/nginx-security.conf  заголовки безопасности и закрытие служебных файлов для nginx
deploy.sh / deploy.ps1 / deploy.cmd  деплой одной командой
data/<id>.js            данные одной контрольной: topics, exam, discrepancies, traps, figures (генерируются)
notes/matan-rk1/*.md    конспекты матана (источник правды); сборщик — tools/build_data.py (список тем внутри скрипта)
notes/angem-rk1/        конспекты аналитической геометрии + exam.json; сборщик — tools/build_exam.py (универсальный)
tools/build_exam.py     универсальная сборка data/<id>.js из notes/<id>/ по exam.json — для всех новых контрольных
tools/figs_angem.py     генератор SVG-рисунков геометрии -> notes/angem-rk1/figs.json
tools/build_materials.py  материалы: materials-src/<id>/ (не в git) -> materials/<id>/
Dockerfile, docker-compose*.yml, DOCKER.md  запуск в контейнере (так работает сервер)
vendor/katex/           KaTeX 0.16.11 (js, css, шрифты woff2) для офлайна
```
Главная страница (`#/`) — карточки контрольных из `manifest.js`; клик открывает материал именно этой контрольной. Нужный файл данных подгружается через `<script>`, поэтому всё работает и по `file://`.

## Правка контента
1. Править `notes/matan-rk1/*.md`.
2. Пересобрать данные:
   ```
   python tools/build_data.py notes/matan-rk1 notes/matan-rk1/93_block_b_figs.json data/matan-rk1.js
   ```
3. Обновить страницу.

Формат конспектов: обычный markdown + `$...$` / `$$...$$`; `<details><summary>…</summary> … </details>` — сворачиваемые доказательства/решения;
строки с `>` и ⚠️ — блок «расхождение со слайдами»; «**Пример…**» + `<details><summary>Решение</summary>` — пример со скрытым решением.
Пометка `[не из лекций]` подсвечивается автоматически.

## Новая контрольная (новый предмет)
Образец — `notes/angem-rk1/`. Программировать ничего не нужно, всё описывается файлами:

1. Создать `notes/<id>/` (например `notes/fizika-rk1/`), положить туда:
   - `exam.json` — название, список тем (`id`, `file`, `num`, `title`, `examRefs`, `kind: "ref"` для справочников), блоки вопросов
     (`id` латиницей, `label` — как показывать, например «Б»), типы задач, тренировочный вариант и тексты страниц
     (`note`, `discTitle`, `warnLabel`, `cardsNote`, `materialsNote`). Скопируйте `notes/angem-rk1/exam.json` и поправьте.
   - `NN_тема.md` — конспекты. Разметка как у матана; рисунок — отдельная строка `{{figure:ключ}}`;
     предупреждение — `> **Неточность в конспекте.** …` (или `> **Расхождение со слайдами.** …`).
   - `90_theory.md` — вопросы с ответами: `### A1. Вопрос`, строка `refs: g01, g02`, ниже ответ.
   - `95_tasks.md` — задачи: раздел `# @тип Название`, задача `### 416. Условие`, подсказка, `<details><summary>Решение</summary> … </details>`.
   - по желанию `94_traps.md` (ловушки), `98_discrepancies.md` (неточности: строки `темы:` и `важность: major|minor|ok`), `figs.json` (рисунки).
2. Собрать: `python tools/build_exam.py notes/<id> data/<id>.js`. Сборщик проверяет ссылки (темы, вопросы, задачи, рисунки)
   и при ошибке пишет, что именно не найдено.
3. Материалы (PDF, фото): положить в `materials-src/<id>/NN_Группа/` и выполнить `python tools/build_materials.py <id>`.
4. Добавить запись в `manifest.js` (новый `subject` или новая контрольная в существующем) и строки сборки в `BUILD_CMDS`
   в `deploy.sh` и `$BuildCmds` в `deploy.ps1`.

Номера вопросов в адресах — латиницей (`A1`, `B3`), показываются по `label` (`А1`, `Б3`). Баллы и вариант необязательны:
если баллов нет, они не выводятся; без `variant` вкладка варианта скрыта; `"scoring": false` — вариант без подсчёта баллов.

## localStorage
Ключи с префиксом id контрольной — прогресс РК1 и РК2 не смешивается:
- `matan-rk1:topic:<topicId>:read` — тема прочитана
- `matan-rk1:exam:<A1|B2|C3…>:known` — вопрос теории «знаю»
- `matan-rk1:task:<1.1…>:done` — задача решена
- `matan-rk1:variant:*` — таймер и баллы типового варианта
- `matan-rk1:disc:onlyMajor` — фильтр расхождений

Общие для всех контрольных: `s30s:theme`, `s30s:lastExam`.

## Известные ограничения
- **Общие темы между контрольными дублируются.** Темы по пределам понадобятся и в РК2 — пока они будут скопированы в `data/matan-rk2.js`.
  Как вынести потом: завести `data/shared/<subject>-<topic>.js`, где каждая тема регистрируется отдельно
  (`S30S.registerTopic({ id: "matan:limits-remarkable", … })`), в файле контрольной хранить только ссылки на id тем,
  а в `manifest.js` у контрольной — список shared-файлов (`deps`), которые оболочка подгружает перед ней.
  Ключи прогресса тем тогда перевести на id темы (`matan:topic:<id>:read`), чтобы «прочитано» переносилось между РК.
- **⚠️ в конспектах и раздел «Расхождения» хранятся раздельно** (текст ⚠️ внутри темы + отдельный массив `discrepancies`),
  а не как ссылка на один источник. При правке расхождения менять оба места (`notes/…/98_discrepancies.md` и саму тему).
- Мини-рендерер markdown понимает подмножество: заголовки, абзацы, списки (один уровень вложенности), таблицы, цитаты, жирный/курсив, `code`, ссылки.
- Дальше — переезд на Django (данные уже отделены от рендеринга: `data/*.js` = JSON внутри `S30S.register(...)`).

## Название

s30s читается как «study of the '30 students»: учёба студентов выпуска 2030, кафедра ИУ7 МГТУ им. Н. Э. Баумана. Логотип: знак «30» в рамке и слово s30s с акцентом на «30» (CSS и встроенный SVG-значок вкладки, без внешних файлов).

## Деплой

Сервер: репозиторий в `/var/www/cheatsheet`, сайт работает в Docker-контейнере на `127.0.0.1:8080`, системный nginx
с сертификатом проксирует на него (подробно — `DOCKER.md`). Скрипт в корне делает всё одной командой:

    .\deploy.cmd                  # Windows (PowerShell), дерево должно быть чистым
    .\deploy.cmd -m "текст"       # закоммитить все изменения этим сообщением и задеплоить
    .\deploy.cmd -DryRun          # только показать команды
    ./deploy.sh [-m "текст"] [--dry-run] [--no-build]   # Git Bash / WSL / Linux

Шаги: 1) пересборка `data/*.js` из `notes/` (список сборок в начале скрипта — добавьте строку для новой контрольной); 2) `git push origin main` (без `-m` скрипт сам ничего не коммитит и остановится, если есть незакоммиченные изменения); 3) `ssh` на сервер, `git pull --ff-only` и `docker compose up -d --build`; 4) проверка, что сайт отвечает HTTP 200.

Настройки: скопируйте `deploy.conf.example` в `deploy.conf` (файл в `.gitignore`) и укажите `DEPLOY_USER`, при необходимости хост, путь и адрес сайта. Нужен вход на сервер по ssh-ключу.

## Режим без персонализации

В `manifest.js` строка `window.S30S_CONFIG = { progress: true };`. Значение `false` убирает «прочитано», «знаю», «решил сам», счётчики и отметки карточек, и ничего из этого не пишется в браузер. Останутся только настройки вида (тема, размер текста, свёрнутые разделы). Ни аккаунтов, ни cookie, ни запросов на сервер сайт не использует.

## Безопасность (минимум для статического сайта)

- Нет внешних скриптов, стилей и шрифтов; нет inline-скриптов. В `index.html` задана CSP (`script-src 'self'`, `default-src 'none'`), политика действует и при открытии из файла.
- Весь вывод экранируется (включая кавычки); в markdown-ссылках разрешены только `#...` и `https://...` (с `noopener`). Адрес вида `#/search/...` больше не позволяет внедрить HTML.
- На сервере подключите `server/nginx-security.conf` внутрь блока `server { }` (затем `sudo nginx -t && sudo systemctl reload nginx`): он закрывает `.git`, `tools`, `notes`, скрипты деплоя, разрешает только GET/HEAD и добавляет заголовки (CSP с `frame-ancestors`, nosniff, HSTS, Referrer-Policy, Permissions-Policy). Самое важное: `.git` лежит в `/var/www/cheatsheet`, без этого блока репозиторий можно скачать по HTTPS.
- `deploy.sh` после выкладки проверяет, что `/.git/HEAD` и другие служебные файлы отвечают не 200, и сообщает об отсутствующих заголовках.
- Другие пакеты в браузере не ставятся, зависимостей npm нет, поэтому риск цепочки поставок ограничен KaTeX в `vendor/`.

## Материалы (фото, PDF, Word, презентации)

Исходники кладутся в `materials-src/<id контрольной>/<NN_Название группы>/` (папка в git не попадает и на сервер не выкладывается). Пример: `materials-src/matan-rk1/02_Слитые_варианты/Вариант 1.jpg`.
Сборка: `python tools/build_materials.py matan-rk1` (её же запускает `deploy.sh`). Нужен Pillow: `pip install pillow`.
Результат в `materials/<id>/`: фото сжимаются до 2200 px по длинной стороне, миниатюры в `_t/`, архивы групп и `all.zip` в `_zip/`, описание в `index.js`. Архивы детерминированные: если файлы не менялись, git разницы не увидит. В git коммитится папка `materials/`.
Страница `#/materials`: списки файлов, сетка миниатюр, просмотр фото (стрелки, свайп, зум колесом/щипком/двойным кликом, перетаскивание), кнопки «Скачать архив» и «Скачать всё одним архивом».

## Защита от перегрузки и «DDoS» (минимум)

Что настроено на уровне nginx (`server/nginx-http.conf` + блок в `server/nginx-security.conf`): лимит запросов и соединений с одного адреса (страницы, миниатюры и архивы по отдельности), короткие таймауты против медленных клиентов, ограничение скорости после 20 МБ на архивах, запрет ссылаться на архивы с чужих сайтов, кэш в браузере для фото и скриптов. Подключение: `sudo cp /var/www/cheatsheet/server/nginx-http.conf /etc/nginx/conf.d/s30s-limits.conf`, затем `sudo nginx -t && sudo systemctl reload nginx` (и `include .../nginx-security.conf;` в `server { }`).
Это защищает от перегруза одним источником и циклического скачивания. От настоящей распределённой атаки nginx на одном сервере не спасёт: для этого перед сайтом ставят Cloudflare (бесплатный тариф: прокси и кэш) или включают защиту у хостинг-провайдера. За прокси в nginx нужен `real_ip` (иначе все посетители будут выглядеть как один адрес Cloudflare и лимиты ударят по всем).

## Работа без интернета

`sw.js` (service worker) сохраняет сайт и материалы в кэше браузера. Нужен HTTPS (на `localhost` тоже работает); при открытии с `file://` воркер не включается, но сайт и так работает локально.

- Первый визит: нужен интернет. Через пару секунд страница сама докачивает данные, шрифты формул, фото и PDF материалов; на странице «Материалы» появляется пометка, что всё сохранено.
- Дальше домен открывается и без сети. Онлайн страница, скрипты, данные и решения берутся с сервера (всегда свежие), а при обрыве или медленной сети (3,5 с) — из кэша. Фото и PDF сначала берутся из кэша.
- Архивы `/materials/_zip/` не кэшируются, скачиваются только онлайн.
- Если заменить фото материалов под тем же именем, поднимите версию кэша `SW_CACHE` в `sw.js` и `app.js` (`s30s-v1` → `s30s-v2`).
- CSP должен содержать `connect-src 'self'; worker-src 'self'` (уже есть в `index.html` и `server/nginx-security.conf`; после правки конфига перезагрузите nginx).
- Экономия трафика: при режиме экономии данных и на 2G фоновая докачка не запускается.
